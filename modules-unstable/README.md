# modules-unstable

**Where every module change lands first.** Not a Git branch — a folder and a catalogue, both on `main`, read only by people who have switched their own Lectio Manager to the release channel it serves — labelled **Experimental** in the Manager, since that is what it means to the students and teachers choosing it; `unstable` everywhere in the code, the stored setting and this folder. Stable users never see any of it. The rule and its reasoning are [ADR-0014](../docs/adr/0014-unstable-first-releases.md); the short version lives in [AGENTS.md](../AGENTS.md).

`modules-unstable/modules.json` is an overlay, not a replacement: an entry here with the same `id` as one in `catalogue/modules.json` replaces it for Unstable users, and an `id` that appears only here is an Unstable-only module. The Manager caches this overlay for five minutes against twenty-four hours for the stable catalogue, so a change here is visible almost immediately.

## Working here

A module being worked on exists twice — the frozen copy stable users have in `modules/`, and the live one here, at least one version ahead. While it is under test the copy in `modules/` is not edited for any reason.

Starting work on a module that is not here yet:

1. Copy it in from `modules/`.
2. Bump its version — `@version` and the version it registers, together. No `-beta` suffixes: plain `MAJOR.MINOR.PATCH`, as [ADR-0003](../docs/adr/0003-static-catalogue-independent-versioning.md) requires of every script in this repository.
3. Point `@updateURL` and `@downloadURL` at this folder's raw path. Tampermonkey follows those, not the catalogue, once a script is installed.
4. Add its entry to `modules-unstable/modules.json` with the same `id` as the stable entry, `status: "unstable"`, and an `installUrl` under `modules-unstable/`.

`node scripts/check-versions.mjs` enforces all of it: each file is checked against the catalogue for the folder it lives in, a copy here must be strictly ahead of what stable ships, the two URLs must point at the folder the file is actually in, and an entry whose file has gone is reported rather than ignored.

## Promotion

Only the repo owner decides when something is promoted, and they say so in those words. The six steps — copy up, rewrite the URLs, bump the patch once more, update `catalogue/modules.json`, delete the file, entry and section from here, re-run the checks — are in [ADR-0014](../docs/adr/0014-unstable-first-releases.md#promoting).

The extra patch bump at promotion is not ceremony. A tester's installed copy points at a `modules-unstable/` URL that promotion deletes; shipping stable on the same number would leave them there silently, updating from a 404 forever. One more bump makes the Manager offer them the stable file instead.

## What is here now

### `Lectio-Change-Radar.user.js`
An experimental timetable watcher — a compact themed radar HUD with urgency states, unseen-change tracking, configurable polling and a rotating local change log. Unstable-only so far; it has never had a stable release, so promoting it would be its first.

`0.6.2` finishes its background-fetch safety net (issue #39). The twenty-second `AbortController` timeout it already had is untouched; what is new is a random offset of up to four seconds on the first check of a page view, and a backoff that doubles from five minutes to a thirty-minute ceiling after two consecutive failed checks and clears on the first one that succeeds. The base and ceiling are the fastest and slowest cadences the Check-frequency setting offers, because a backoff shorter than the poll interval would be stepped straight over and one longer than half an hour would outlast the usefulness of the thing being watched. A tick still never stacks on a check in flight, and pressing Refresh or changing what is watched clears the backoff rather than being swallowed by it. Its `pagehide` teardown now suspends rather than switches off, so a page restored from the back/forward cache goes on checking instead of sitting there dead.

`0.7.0` also reports to the Manager's problem log (issue #24): a fetched week that rendered `.s2skemabrik` blocks none of which parsed is raised as drift, rather than being reported to the user as a week with no changes in it.

`0.7.1` closes the last gap in that safety net (issue #42): live `AbortController`s are now tracked in a Set and aborted when the page goes away, not only when the twenty-second timeout fires. It happens in `suspendPolling()`, which `pagehide` calls before it splits on `event.persisted`, so a page frozen for the back/forward cache stops holding a Lectio request open and still resumes checking on a persisted `pageshow`. The timeout itself is unchanged, and a controller is removed from the Set in the same `finally` that clears its timeout, so nothing accumulates.

`0.8.0` bounds the change log by bytes and drops dead identities (issue #29). The log was capped by entry count only, but a snapshot of every watched week sits in the same value, so what is written is now capped in characters as well, oldest log entries first — the state on screen is untouched, only what is stored is trimmed. Keys are scoped per Lectio identity, and a browser accumulated a whole snapshot for every identity it had ever seen; one that has not been polled in two months is now dropped whole on load. What it stores is declared to the Manager, with the snapshot prunable and the settings and last-seen mark not.

`0.9.0` asks the Manager for a turn before each request in a check (issue #40). A check is a burst of one request per watched week plus any extra source, which is exactly the kind of thing worth spreading out against the other modules. It fails open on this module's own clock, which is the whole of it: no answer within 1.2s means no Manager, an old Manager or one that has stopped - the same case, and it means go - and a request the Manager acknowledged waits at most 8s more before going anyway and handing the turn straight back. That 1.2s is paid once per page view, not once per request: a request that goes unanswered is remembered, and the next one does not wait at all until something answers again. Nothing the Manager sends can make it wait longer. See [`docs/manager-request-slots.md`](../docs/manager-request-slots.md).

`0.9.2` reads the assignment list and the absence page it was always pointed at (issue #59). Both parsers were written against the query keys a hand-written fixture guessed — `exerciseid=` and `absenseId=` — and the real pages, once saved into `tests/fixtures/pages/`, link with `exeid=` and `ActivityAbsenceRegistration.aspx?id=`; so every install on the default settings had been watching assignments and reporting nothing, for as long as the feature existed. Both shapes are accepted now, the absence one matched on the page name as well as the parameter so a bare `id=` elsewhere cannot be read as a registration. Where a table names its columns the name wins over the pattern: the deadline comes from the Frist column rather than the first date-shaped cell (the note beside it is free text somebody wrote), and a grade only from a Karakter column, because the teacher's list has a column of counts and 7 students not handed in read as "Grade 7". Rowspans are lined up first, since the week column spans rows and the later rows of a week are a cell short of the header. A registration is titled by its lesson block, read once although that page renders every block twice. The per-hold percentage half of the absence parser is left as written: it is for the student page, `subnav/fravaerelev.aspx`, which nobody has saved yet, and the teacher page carries no percentages. And because a parser that has never seen a row looked exactly like a quiet week — which is how this went unnoticed — a page that is plainly the list, with data rows, and no row read now reports `assignment-rows` or `absence-rows` drift to the Manager's problem log, while the last good capture is kept.

`0.9.3` moves `ASSIGNMENT_STATUS_PATTERN` from beside the assignment parser, far below the boot block, up beside `TOOLTIP_FIELD_PATTERN` and `GRADE_TOKENS` with the other constants above it (issue #58). `init()` runs during the file's own evaluation, and a module-scope `const` declared after it is in its temporal dead zone until evaluation reaches it. Only `parseAssignments()` read the pattern, off a timer or an event, so nothing was broken; `scripts/check-boot-order.mjs` cannot tell that apart from a live read, and this module now passes it instead of being listed as a deferred finding. No behaviour changes.

`0.9.4` fixes the two halves of issue #66. Automatic location resolved to the dock only once `lectio-manager:discover` had been heard, but Tampermonkey injects the Manager and every module at `document-idle` in an order nothing controls, and the Manager fires its one start-up Discovery synchronously during its own evaluation: on a page where the Manager was evaluated first, that event went out before this module had a listener, and after the 2.5s grace the radar fell back to floating, every reload. Automatic now also reads the dock root the Manager builds during that same boot (`#lectio-manager-dock-root`, read-only, never touched), so either order lands in the dock, and a Discovery that does arrive later moves a waiting radar straight in rather than leaving it to the next poll. Second, no button in the floating radar's panel answered a mouse click, Settings included: a click focuses the button it lands on, the `focusin` handler rebuilt the whole HUD, and the button under the pointer was replaced between `mousedown` and `mouseup`, so no `click` was ever fired. Hover and focus now only toggle the panel open or closed on the nodes already there.

`0.9.5` words all thirty settings and their six sections in Danish as well as English (issue #60). The frozen `SETTING_SCHEMA` list became `SETTING_TEXT`, one `en` and one `da` side with a label, a help line and one line per option value for each setting, and `settingSchema()`, which builds the list fresh through the module's existing `radarLanguage()` every time it is read - by `registerWithManager()`, which now also listens on `lectio-manager:language`, and by the floating radar's own settings panel, so both surfaces speak the same language. Keys, types, defaults, option values and the section order are written once in `settingSchema()` and cannot differ between the two. The module's name stays Change Radar in the Danish help text. The two sides sit between `// i18n:en` / `// i18n:da` / `// i18n:end` markers; because each setting's entry is one line, `scripts/check-i18n.mjs` compares the thirty setting keys plus `sections`, not the words inside each entry.
